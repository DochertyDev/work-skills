## Dependency and licensing checks

Read all 11 entrypoints completely. Inventoried and statically scanned each candidate directory (86 files total), inspected the referenced permissions/governor-limit and diagram documents, SOQL references/hook, log references, architecture rubric/checklists, decision formats/scoring/modifier, integration credential scripts and selected guidance, and relevant parent manifests/licenses. This was targeted review: excluded example trees, linked sibling workflows, plugin internals, external APIs, downloaded generators, and third-party runtime packages are **not comprehensively security-audited**. Their unresolved behavior is not inherited by accepted folders.

- **Required retained dependencies:** none beyond an agent able to read the user's local text files. Each accepted folder contains exactly the skill, provenance, and upstream license. Related skill names are optional routing guidance, not missing local file dependencies.
- **Optional runtime enhancements:** diagram preview renderer; explicitly authorized org log retrieval with an existing CLI. Missing tools yield source/offline analysis and an accurate limitation, never fabricated execution.
- **Documentation dependencies:** authoritative platform links are consulted for version-sensitive behavior. CL permissions depends on `../../references/governor-limits.md`, outside its skill folder. ADA needs five format files, the scoring methodology, and the conditional agentic modifier at repository-root paths. These are not portable folder-only installs.
- **Unresolved runtime dependency:** SF SOQL's hook imports `code_analyzer.live_query_plan` from a computed shared directory; that module was not found in the inspected source tree. The import failure is swallowed, degrading silently to regex checks. No live-plan capability was tested.
- **Development dependencies:** source npm manifests and sample-sync tooling belong to upstream packaging, not the accepted Markdown workflows. Nothing was installed or executed from the source repositories. No source-repository configuration, plugin lifecycle hooks, telemetry, bundled language servers, or MCP proxies is redistributed.

AC's root MIT grant credits GitHub, Inc.; no candidate-specific override or additional asset exists. CL's root Apache-2.0 grant credits Clientell; candidate frontmatter agrees, and no separate NOTICE or nested license was found. SF's root `LICENSE.txt` carries Salesforce's copyright and Apache-2.0 grant. Its development plugin also carries that license and a NOTICE about unbundled third-party binaries; those binaries are omitted. ADA's root MIT grant credits Dave Norris. No unresolved redistribution grant blocks the selected files. This does not certify licenses of omitted upstream runtimes or external documentation, which are not copied.

Each adaptation preserves the complete applicable upstream license in its folder, records original repository/path/commit/author and Git-blob SHA-256 in `PROVENANCE.md`, and carries a prominent modification notice. No source content is relabeled as original MIT work. Existing per-skill provenance conventions are sufficient; no new central licensing framework is introduced.

## Validation and limitations

Reviewed [Agent Skills specification](https://agentskills.io/specification) and [official Codex skills documentation](https://learn.chatgpt.com/docs/build-skills) for manifest/discovery requirements. No installation procedure is changed. Standard `name`, `description`, `license`, and string-valued `metadata` are used; no Claude-only fields or tool grants remain in new manifests.

Offline checks cover names, description lengths, metadata/category/source consistency, local Markdown links, catalog coverage, file inventory, prominent change notices, pinned provenance, and license-text equivalence against Git blobs (ignoring line endings and the removed trailing blank line in the SF license). Public-content checks cover credential patterns, private paths/hosts, real account data, unfinished template prompts, executable files, and accidental runtime/config inclusion. `git diff --check`, explicit staging, staged diff, and outgoing commit review are required before publication.

The available Python runtimes have no YAML package and no parser was installed. New manifests deliberately use a restricted scalar-only YAML shape; structural/scalar checks and manual review validate that shape, **not a general YAML-parser test**. Existing manifests/template are unchanged. No renderer, Salesforce CLI, authentication, org mutation, external script, live agent discovery/routing, or Salesforce-backed test was run.

Remaining risks: platform behavior changes across API versions; static review cannot prove generated Apex compiles, a Flow behaves correctly, a diagram renders, or a log hypothesis is causal. Verify against project-specific source and a separately authorized nonproduction test. Deferred candidates need focused correction and dependency validation before reconsideration; rejected integration helpers need redesigned secret/mutation handling. No Salesforce or other-agent integration is certified by this PR.
